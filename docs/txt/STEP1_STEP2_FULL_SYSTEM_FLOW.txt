PHASE 2 — STEP 1 REVERSE ENGINEERING (MULTIMODAL INGESTION & KNOWLEDGE GRAPH)
================================================================================

PURPOSE OF STEP 1:
Ingests raw multimodal study materials (PDF documents, image diagrams, plain text,
or lecture videos), validates signatures, normalizes content into canonical ContentUnit
abstractions, extracts conceptual knowledge graphs with prerequisite dependencies,
chunks text semantically with Layer A provenance, and syncs dense vectors to Qdrant.

ENTRY POINT:
- Endpoint: POST /upload
- Handler: app.api.upload.upload_file()
- Router File: app/api/upload.py

EXECUTION SEQUENCE:
1. File Validation & Registration (app/services/registry.py::register_source):
   - Enforces size limit (<500MB) and checks magic bytes (PDF, PNG, JPG, MP4, MOV, MKV, TXT).
   - Computes SHA-256 hash. If existing, increments version and records parent_source_id.
   - Saves original file to storage/uploads/{source_id}/original.<ext>.
   - Writes SourceRecord to storage/registry/sources_index.json.
2. Modality Dispatching (app/services/dispatcher.py::dispatch):
   - PDF -> app/services/extractor.py::extract_from_pdf (PyMuPDF blocks, bboxes, diagrams).
   - Text -> Semantic paragraph splitting with char offsets.
   - Image -> app/services/vision.py::describe_image_file (Gemini Vision diagram analysis).
   - Video -> app/services/video/pipeline.py::process_video_units (FFmpeg WAV extraction +
     faster-whisper ASR + OpenCV perceptual frame deduplication + Gemini Vision + temporal fusion).
3. Canonical Normalization:
   - Output: Uniform List[ContentUnit] (content_id, source_id, text, page_number,
     timestamp_start, timestamp_end, bbox, sequence_index).
   - Stored in: storage/registry/{source_id}/content_units.json.
4. Structure Detection & Knowledge Graph (app/services/structurer.py):
   - Discovers curriculum hierarchy (chapters, sections, concepts, prerequisite DAG).
   - Resilient Fallback: If Gemini quota 429 occurs, switches to regex/heuristic extractor.
   - Stored in: storage/registry/{source_id}/knowledge_graph.json.
5. Semantic Chunking & Vector Store Sync (app/services/chunker.py & app/db/vector_store.py):
   - Concept-aware chunking produces RichChunk objects carrying Layer A provenance.
   - Computes 768-dim embeddings via gemini-embedding-2.
   - Upserts into Qdrant collection visualai_layer_a using deterministic UUIDv5 IDs.
6. 5-Tier Quality Validation Gateway (app/services/validator.py):
   - Verifies file, content, chunk, concept DAG, and vector storage points.
   - Marks source status as "READY" in sources_index.json.

PHASE 3 — STEP 2 REVERSE ENGINEERING (ADAPTIVE ASSESSMENT & PROFILING)
================================================================================

PURPOSE OF STEP 2:
Generates grounded diagnostic quizzes strictly from authoritative source material,
administers assessments, evaluates submissions, detects root prerequisite knowledge gaps,
enforces anti-loop guardrails, and produces a tailored Video Target Matrix.

ENTRY POINTS:
- POST /assessment/start (Initialize session & generate questions)
- POST /assessment/submit (Submit student answers for grading)
- GET  /assessment/profile/{student_id}/{source_id} (Inspect cumulative profile)
- GET  /assessment/video-target/{student_id}/{source_id} (Inspect Video Target Matrix)

EXECUTION SEQUENCE:
1. Session Initialization & Snapshotting (app/api/assessment.py):
   - Asserts source status == "READY".
   - Generates unique session_id: SESS_<uuid4_hex>.
   - Embeds ConceptSnapshot directly into AssessmentSession for offline execution.
   - Persisted to storage/assessment_sessions/<session_id>.json.
2. Dynamic Assessment Planning (app/services/assessment/planner.py):
   - Cold Start balance: ~30% foundational, ~40% intermediate, ~30% advanced.
   - Prerequisite Pairing: Automatically pairs parent prerequisites with advanced concepts.
   - Allocates primary concept candidates and backup reserve pool.
3. Source-Isolated Grounded Question Generation (app/services/assessment/generator.py):
   - Queries Qdrant collection visualai_layer_a filtered strictly by source_id.
   - Prompts pluggable LLM provider (Gemini, Ollama, or Mock) to craft 4-option MCQs.
   - Deterministic Fallback: Derives questions from concept definitions if LLM is unavailable.
4. 3 Quality Validation Gateways & Backfilling (app/services/assessment/validator.py):
   - Gateway 1: Structural format (4 options, valid correct index, non-empty stem).
   - Gateway 2: Grounding vocabulary overlap (>10% keyword match with source chunks).
   - Gateway 3: Non-duplication (Jaccard similarity < 0.6 between questions).
   - Automatic Reserve Backfilling: Replaces failed candidates from reserve pool.
5. Sanitized Quiz Delivery:
   - Full Question models saved in session file with hidden correct answers.
   - Strips answer keys to produce SafeQuestion objects dispatched to the client.
6. Submission Grading & Engine Safeguards (app/services/assessment/engine.py):
   - Compares answers with hidden answer key; computes concept scores.
   - Prerequisite Gap Detection: Flags failed child concept + failed parent prerequisite.
   - False-Mastery Safeguard: Requires consecutive correct threshold (default: 2).
   - Anti-Loop Kill Switch: If failure count > 3, sets status to REQUIRES_HUMAN_FALLBACK.
   - Saves StudentLearningProfile to storage/learning_profiles/<student_id>_<source_id>.json.
7. Video Target Matrix Generation (app/services/assessment/video_target.py):
   - Evaluates unmastered concepts; filters out mastered and kill-switch concepts.
   - Scales target duration by difficulty: Foundational = 30s, Intermediate = 45s, Advanced = 60s.
   - Attaches provenance chunk_ids and source page numbers.
   - Persists to storage/video_targets/<student_id>_<source_id>.json.

PHASE 4 — STEP 3 REVERSE ENGINEERING (TARGETED AI VIDEO GENERATION ENGINE)
================================================================================

PURPOSE OF STEP 3:
Consumes unmastered remediation targets from the Step 2 Video Target Matrix,
retrieves authoritative source chunks and diagrams from Step 1, generates a timed
multi-scene script, synthesizes neural voiceover audio, renders 1080p animated visual
slide cards, multiplexes audio and video with FFmpeg, and delivers streaming MP4
lessons with synchronized WebVTT captions.

ENTRY POINTS:
- POST /video/generate            (Trigger rendering for unmastered concept)
- GET  /video/status/{job_id}     (Poll job progress and current stage)
- GET  /video/{video_id}/stream   (Stream rendered MP4 video)
- GET  /video/{video_id}/subtitles (Return WebVTT subtitle track)
- GET  /video/list/{student_id}   (List rendered videos for student)

KEY MODULES IN app/services/video_gen/:
1. schemas.py:
   - VideoScene: Sequential scene index, scene_type ("title_hook", "concept_breakdown",
     "diagram_focus", "formula_derivation", "summary_takeaway"), title, narration,
     onscreen_bullets, highlight_text, diagram_cu_id, duration_seconds.
   - VideoScript: video_id, student_id, source_id, concept_id, concept_name, difficulty,
     target_total_seconds (30/45/60), scenes list, word count, source_chunk_ids.
   - VideoRenderJob: job_id, video_id, status ("pending", "generating_script",
     "synthesizing_voiceover", "rendering_visuals", "muxing_media", "completed", "failed"),
     progress_percent (0-100), current_stage, video_file_path, subtitles_file_path.
2. script_generator.py:
   - Assembles grounded context from RichChunks and ContentUnits.
   - Enforces strict duration word count budget (~130-150 WPM):
     * 30 seconds: ~65-75 words
     * 45 seconds: ~100-115 words
     * 60 seconds: ~130-150 words
   - Prompts LLM to structure a pedagogical 3-Act micro-lesson:
     * Act 1 (Hook & Core Question): 15-20% duration
     * Act 2 (Breakdown & Visual Diagram): 60-70% duration
     * Act 3 (Takeaway & Mental Anchor): 15-20% duration
   - Deterministic Fallback: Generates 3-act script directly from concept definition.
3. audio_synthesizer.py:
   - Multi-tier TTS engine:
     * Tier 1: Edge-TTS neural voice ("en-US-ChristopherNeural" or "en-US-GuyNeural").
     * Tier 2: pyttsx3 offline system TTS fallback.
     * Tier 3: Deterministic mock audio generator for zero-network testing.
   - Synthesizes per-scene WAV files (scene_{i}_audio.wav) and master track (master_audio.wav).
   - Accurately measures exact audio durations to drive visual synchronization.
4. visual_renderer.py:
   - Renders 1080p (1920x1080 @ 24 FPS) visual scene cards via Pillow (PIL).
   - Dark-mode aesthetic: Slate backdrops, gradient accents, clear sans-serif typography.
   - Visual Components: Title banners, bullet cards, highlighted formula boxes,
     embedded source diagram images (from diagram_cu_id), and dynamic progress bars.
   - Encodes frames directly to MP4 clips via OpenCV cv2.VideoWriter (scene_{idx}_clip.mp4).
5. muxer.py:
   - Stitches scene clips using FFmpeg concat demuxer (raw_video.mp4).
   - Multiplexes visual video with master audio using H.264 video and AAC audio:
     ffmpeg -y -i raw_video.mp4 -i master_audio.wav -c:v libx264 -pix_fmt yuv420p
            -c:a aac -b:a 192k -shortest final_video.mp4
   - Generates synchronized WebVTT subtitle track (subtitles.vtt) with cue timestamps.
6. pipeline.py:
   - High-level orchestrator: Coordinates script generation, audio synthesis, visual rendering,
     muxing, and master video cataloging.
   - Manages isolated workspace: storage/runtime/videos/<video_id>/.
   - Registers completed lessons in storage/runtime/videos/videos_index.json.

PHASE 5 — STEP 4 REVERSE ENGINEERING (REMEDIATION VERIFICATION & RE-TESTING LOOP)
================================================================================

PURPOSE OF STEP 4:
Closes the pedagogical feedback loop. After a student watches a remedial video lesson,
Step 4 administers a targeted 1-2 question verification check testing application and
misconception resolution, evaluates responses, transitions concept mastery from LEARNING
to MASTERED, dynamically resolves the Video Target Matrix, and updates the student profile.

ENTRY POINTS:
- POST /remediation/start   (Initialize verification re-test session)
- POST /remediation/submit  (Grade answers, transition mastery, resolve target)

KEY MODULES IN app/services/remediation/:
1. engine.py::create_remediation_session:
   - Retrieves concept metadata from KnowledgeGraph.
   - Generates fresh grounded verification questions using specialized variants:
     * "application": Evaluates concrete scenario application of the concept.
     * "misconception": Evaluates resolution of the specific conceptual trap.
   - Strips hidden answer key to produce SafeQuestion objects for client delivery.
   - Assigns session_id: SESS_REM_<uuid4_hex> and persists to storage/assessment_sessions/.
2. engine.py::evaluate_remediation_submission:
   - Compares student answers against hidden ground truth in stored session.
   - Passing threshold: score percentage >= 70.0%.
   - When Passed:
     * Concept status transitions: "LEARNING" -> "MASTERED".
     * Increments correct_attempts and consecutive_correct count.
     * Updates StudentLearningProfile: removes from weak_concepts, adds to strong_concepts.
     * Dynamic VideoTargetMatrix Resolution: Automatically removes the cleared concept from
       matrix.videos. If all videos resolved, sets decision to "ALL_MASTERED".
   - When Failed:
     * Increments failure attempts; resets consecutive_correct = 0.
     * Anti-Loop Kill Switch: If failure attempts > 3, sets status to "REQUIRES_HUMAN_FALLBACK",
       removes concept from video queue, and alerts human instructor.

================================================================================

1. VECTOR STORE: QDRANT (Layer A)
   - Collection: visualai_layer_a
   - Metric: Cosine Distance
   - Dimension: 768 dimensions (gemini-embedding-2)
   - Point ID: Deterministic UUIDv5 (uuid5(NAMESPACE_DNS, f"{source_id}::{chunk_id}::{text[:100]}"))
   - Isolation: Filtered queries strictly require must=[FieldCondition(key="source_id", match=MatchValue(value=source_id))]

2. STRUCTURED FILE PERSISTENCE (ATOMIC JSON STORES):
   - storage/registry/sources_index.json: Master registry of all uploaded materials.
   - storage/registry/{source_id}/content_units.json: Normalized extraction units.
   - storage/registry/{source_id}/knowledge_graph.json: Conceptual DAG and blueprints.
   - storage/assessment_sessions/{session_id}.json: Step 2 and Step 4 quiz sessions with hidden answer keys.
   - storage/learning_profiles/{student_id}_{source_id}.json: Student cumulative mastery profiles.
   - storage/video_targets/{student_id}_{source_id}.json: Video Target Matrices for remediation.
   - storage/runtime/videos/videos_index.json: Global catalog of all completed video lessons.
   - storage/runtime/videos/<video_id>/: Isolated per-video workspace containing scripts, audio, clips, and final MP4.

================================================================================

SCENARIO: Complete Student Journey through All 4 Steps

1. INGESTION (Step 1):
   - User uploads "physics_textbook.pdf" to POST /upload.
   - app/api/upload.py::upload_file() buffers stream to storage/uploads/temp.pdf.
   - app/services/registry.py::register_source() validates magic bytes, computes SHA-256, assigns SRC_01.
   - app/services/dispatcher.py::dispatch() calls extractor.py::extract_from_pdf().
   - app/services/structurer.py::process_structure_and_concepts() prompts Gemini, outputs KnowledgeGraph.
   - app/services/chunker.py::create_rich_chunks() creates RichChunks with Layer A tags.
   - app/db/vector_store.py::upsert_chunks() embeds chunks via gemini-embedding-2, writes to Qdrant.
   - app/services/validator.py::validate_ingestion_quality() validates 5 tiers, sets status="READY".

2. ASSESSMENT (Step 2):
   - User triggers POST /assessment/start with source_id="SRC_01", student_id="student_1".
   - app/services/assessment/planner.py plans 5 questions with 30/40/30 distribution.
   - app/services/assessment/generator.py retrieves source-isolated chunks from Qdrant, generates MCQs.
   - app/services/assessment/validator.py validates format and grounding; backfills if needed.
   - Full questions saved in storage/assessment_sessions/SESS_01.json.
   - SafeQuestions (hidden answers stripped) returned to student.
   - Student submits answers to POST /assessment/submit.
   - app/services/assessment/engine.py grades submission. Student scores 40% on "Centripetal Acceleration".
   - Concept status set to "LEARNING". Attempts incremented to 1.
   - app/services/assessment/video_target.py builds VideoTargetMatrix:
     * VideoTarget("Centripetal Acceleration", difficulty="intermediate", target_seconds=45).
     * Saved to storage/video_targets/student_1_SRC_01.json.

3. VIDEO GENERATION (Step 3):
   - User clicks "Generate Video" on dashboard -> triggers POST /video/generate.
   - app/api/video.py::generate_video_endpoint() checks kill switch (not triggered), creates job JOB_VGEN_01.
   - Background task executes app/services/video_gen/pipeline.py::execute_video_generation_pipeline().
   - script_generator.py crafts 3-act script constrained to 45s (105 words), saves script.json.
   - audio_synthesizer.py generates neural voiceover narration tracks via Edge-TTS (master_audio.wav).
   - visual_renderer.py composes 1080p visual cards with diagram callouts via Pillow/OpenCV (scene clips).
   - muxer.py stitches clips and muxes audio/video via FFmpeg -> storage/runtime/videos/VID_01/final_video.mp4.
   - muxer.py generates subtitles.vtt.
   - Job completed (100%). Video streamable via GET /video/VID_01/stream.

4. REMEDIATION VERIFICATION (Step 4):
   - Student watches video in embedded modal.
   - Student clicks "Verify Mastery" -> triggers POST /remediation/start.
   - app/services/remediation/engine.py::create_remediation_session() generates 1 targeted
     "application" question for "Centripetal Acceleration".
   - Dispatches SafeQuestion under session SESS_REM_01.
   - Student submits correct answer to POST /remediation/submit.
   - evaluate_remediation_submission() grades answer: 100% (Passed >= 70%).
   - Mastery transition: "Centripetal Acceleration" updated from "LEARNING" -> "MASTERED".
   - StudentLearningProfile updated in storage/learning_profiles/student_1_SRC_01.json.
   - Dynamic Resolution: "Centripetal Acceleration" removed from VideoTargetMatrix.
   - VideoTargetMatrix decision updated to "ALL_MASTERED". Closed feedback loop complete!

PHASE 12 — AI / LLM / VISION / AUDIO SYNTHESIS / VIDEO COMPOSITION FLOW
================================================================================

1. AI / LLM INFERENCE STACK:
   - Structurer (Step 1): Google Gemini gemini-3.5-flash extracts chapters, concepts, and DAG links.
   - Question Generator (Step 2 & Step 4): Prompts Gemini (or Ollama/Mock) with strict JSON schema.
   - Video Scriptwriter (Step 3): Prompts Gemini with duration-bounded word budgets for 3-act lessons.
   - Video RAG Agent: Synthesizes pedagogical answers using retrieved Qdrant Layer A text chunks.

2. VISION PROCESSING STACK:
   - Diagram Analysis (Step 1): PyMuPDF extracts embedded textbook figures; Gemini Vision generates descriptions.
   - Video Frame Deduplication (Step 1): OpenCV samples video every 12s; compares 32x32 grayscale thumbnails
     (<4% mean absolute difference skipped as duplicate slides). Gemini Vision describes kept keyframes.

3. AUDIO SYNTHESIS & RECOGNITION STACK:
   - Speech Recognition (Step 1): faster-whisper (large-v3) transcribes lecture audio with word/segment timestamps.
   - Voiceover Synthesis (Step 3): Edge-TTS synthesizes natural neural narration (en-US-ChristopherNeural).
     Fallback to pyttsx3 or deterministic mock audio generator.

4. VIDEO COMPOSITION & RENDERING STACK:
   - Visual Composition (Step 3): Pillow (PIL) renders anti-aliased 1080p slide cards (titles, bullets,
     highlight cards, embedded textbook diagrams, progress bars).
   - Frame Encoding (Step 3): OpenCV cv2.VideoWriter encodes frames into MP4 scene clips.
   - Multiplexing & Stitching (Step 3): FFmpeg concatenates video clips, multiplexes audio and video tracks,
     and formats synchronized WebVTT subtitles.


================================================================================
PHASE 13 — INTER-STEP CONNECTION CONTRACTS
================================================================================

1. STEP 1 -> STEP 2 CONTRACT:
   - Output: source_id string with status == "READY" in storage/registry/sources_index.json.
   - Artifacts: knowledge_graph.json, content_units.json, and Qdrant visualai_layer_a collection.
   - Step 2 requires zero knowledge of the original file format (PDF/TXT/Video).

2. STEP 2 -> STEP 3 CONTRACT:
   - Output: VideoTargetMatrix at storage/video_targets/<student_id>_<source_id>.json.
   - Directives: target_seconds (30s foundational, 45s intermediate, 60s advanced), chunk_ids, page numbers.
   - Anti-Loop Guardrail: Step 3 NEVER generates videos for concepts in human_intervention_concepts.

3. STEP 3 -> STEP 4 CONTRACT:
   - Trigger: Video playback completion or learner clicks "Verify Mastery" in dashboard.
   - Payload: student_id, source_id, concept_id.
   - Objective: Administer 1-2 focused verification questions to confirm comprehension.

4. STEP 4 -> INSTRUCTOR PORTAL CONTRACT:
   - If verification passes: Concept transitions to MASTERED; VideoTargetMatrix removes the target.
   - If verification fails > 3 times: Concept transitions to REQUIRES_HUMAN_FALLBACK.
   - Alert Generation: HumanInterventionAlert surfaced in Instructor Portal for manual resolution.
