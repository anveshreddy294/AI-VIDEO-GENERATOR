## HTTP_422_DIAGNOSIS

### REPRODUCED_OFFLINE:
**YES.**
Simulating model outputs containing standard LLM formatting (markdown code fences with conversational text, trailing commas in JSON arrays/objects, string-formatted concepts, or missing top-level topic fields) caused `Teaching.model_validate_json(resp_clean)` to throw `pydantic.ValidationError`.

### ROOT_CAUSE_IF_CONFIRMED:
1. **Unforgiving Raw JSON Parsing**: `app/services/educational_content.py` previously stripped only an exact triple-backtick fence at the very boundary of the string. Any preamble text (e.g., `Here is the lesson:\n```json ...````), trailing commas, or string-array `key_concepts` failed direct Pydantic parsing.
2. **Generic Exception Swallowing**: `app/api/educational_content.py` caught `(ValidationError, ValueError)` and raised HTTP 422 with generic code `{"code": "EDUCATIONAL_CONTENT_INVALID"}` without logging validation locations or error types.
3. **Frontend Misattribution**: In `app/static/learning.js`, `safeError(status, value)` did not have a specific branch for `code === 'EDUCATIONAL_CONTENT_INVALID'`, causing the generic HTTP 422 fallback on line 62 to trigger:
   `"The selected learning scope is not valid. Choose it again."`
   This made a content normalization failure appear to the user as a legacy session navigation/scope failure.

### FIX_IMPLEMENTED:
1. **Robust JSON Normalizer**: Implemented `normalize_teaching_json(raw: str, fallback_topic: str) -> dict[str, Any]` in `app/services/educational_content.py`:
   - Extracts outermost `{...}` JSON block regardless of conversational preambles or markdown wrappers.
   - Cleans trailing commas before closing braces/brackets.
   - Coerces string concepts to `{"name": str, "explanation": str}` objects.
   - Ensures `examples` and `equations` are flat string lists.
   - Injects `fallback_topic` if `topic` is missing or empty.
   - Preserves strict validation failure for genuinely invalid input (e.g., raw prose or unauthorized source claims).
2. **Safe Diagnostic Exception Logging**: Installed sanitized logging in `app/api/educational_content.py`:
   - Logs `[(item["loc"], item["type"])]` for `ValidationError` with `include_input=False` and `include_context=False`.
   - Logs `type(error).__name__` for `ValueError`.
   - Sets `exc_info=False` to prevent unrestricted stack traces or sensitive memory dumps in production logs.
3. **Frontend Error Translation**: Added explicit handlers in `app/static/learning.js:safeError`:
   - `code === 'EDUCATIONAL_CONTENT_INVALID'` -> `"Could not generate educational lesson for this topic. Please try again."`
   - `code === 'LESSON_NOT_FOUND'` -> `"The requested educational lesson was not found."`

### FILES_CHANGED:
