# Offline test storage and authentication modes

Pytest disables python-dotenv loading before importing application configuration. The developer's ignored .env is never a test configuration source. Import-time defaults use offline models and temporary storage; external Supabase credentials are removed from the pytest child process. This has no effect on the running application or its environment.

Tests that exercise legacy file-backed parser, assessment, mastery, vision, registry and pipeline behavior explicitly declare `pytestmark = pytest.mark.usefixtures("file_storage_mode")`. Their original stage, grounding, retry and business-status assertions remain unchanged. The Step 12 suite uses the same root fixture instead of altering process environment during collection.

Supabase source, Auth and frontend-boundary suites explicitly declare `supabase_storage_mode`. It keeps Supabase registry guards and ownership checks active and installs a rejecting HTTP mock transport; individual tests supply their controlled repository/Auth transports. No fixture universally resets database_provider to file during each test. The factory-default test explicitly selects file mode and now checks the documented default precisely. The verified-context factory test explicitly selects Supabase mode.

Every test gets isolated mutable directory settings, profile/session legacy aliases, the instructor analytics profile-path alias, and an independent Qdrant client. Dependency overrides are restored on teardown. Model overrides remain the established offline test configuration; production model routing and embedding configuration are unchanged.

`authenticated_client` supplies test-only dependency overrides for the existing Auth dependency and the source-repository boundary. The source dependency calls Auth directly rather than resolving it through Depends, so both existing seams are overridden within the fixture. The repository has a deterministic UUID owner and an offline transport. The fixture restores all overrides and closes its transport. No production authentication bypass is introduced. Auth tests do not use this fixture.

New regression tests verify file isolation, Supabase registry/factory rejection, anonymous 401, authenticated missing-job 404, authenticated admission-control 429, job-owner isolation, override cleanup and dotenv exclusion. Existing source tests continue to cover authenticated canonical commits, no local fallback, owner mismatch rejection and caller-supplied identity rejection. Existing Auth tests retain server signature-boundary checks, expiry/issuer/audience/UUID validation, profile RLS headers and secret-free errors.

Architectural observations: unconfigured/file remains the documented config default; explicit Supabase mode requires verified source context. Legacy reassessment/video/assessment functions still call local registry functions, so their algorithm tests use the file fixture. This task does not route those unintegrated legacy production services through a new repository architecture. Imported mutable directory aliases are a structural isolation concern; test fixtures patch the existing aliases rather than changing production services.
